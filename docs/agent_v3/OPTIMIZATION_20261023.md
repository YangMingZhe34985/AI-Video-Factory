旧代码的典型路径：先 1–4 轮读取 Skill、Schema 与工具合同，再 write → check_plan → 修正 → submit 循环。新代码：同一轮写需求摘要并内联提交，通过即进入审核。

提示词质量：新代码生成的提示词按五维度写作（画质风格、主体造型、场景光影、运镜动作、声音），图生视频只写动态，图生图带身份锁定，图片写“画面无文字、无水印”；均针对实际主题原创（示例已改为与测试无关的主题，避免照抄）。旧代码的视频提示词基本是用户原话。

## 改动

1. **内联提交**：`submit_plan({plan})` 一次完成保存、编译、试运行、提交；函数 Schema 不重复导出完整计划结构。
2. **Producer 简单任务速通**：不预读，同一轮写 brief + 提交；内置 4 个可编译示例（文生视频、首帧 + 图生视频、上传图改图、风格选择后动画），由测试保证示例始终能一次提交成功；多镜头默认拼接成一个成片。
3. **模型偏好**：从原话中提取模型或系列名（最长匹配，`wan2.7` 不会匹配 `wan2.70`）；系列同时约束其拥有的图片与视频模型；原话中的“视频/图片”范围词优先。
4. **wan2.6-image**：Agent 计划提交时用交错模式并设 `max_images=n`（该模式忽略 n、默认 5 张；关闭交错是图像编辑模式，需要输入图片）。
5. **SAR**：未声明的 SAR 按 1:1 处理（FFmpeg 语义），Mock 素材与真实输出形态一致。
6. **诊断**：参数错误给出 `fields` 与 `allowed_params`；交付输出名错误给出该工具的可用输出。
7. **提示词标准**：t2v / i2v / t2i-prompt-writing 重写（提炼自 `factory_prompts/`），Producer、Director、Prompt Smith 引用。

## 验证

- 后端全量回归（12 组并行，约 11 分钟）：见 PROGRESS 记录。新增 5 个测试文件（内联提交、示例可提交、模型偏好解析、图片张数、未声明 SAR），按新决策调整 3 个旧测试（test_simple_plan、test_v6_policy、test_v6_agent_scenarios）。
- 真实验证：两段真实 wan2.7 视频按 16:9 1280×720 拼接，stream_copy 无重编码，QC 尺寸与比例通过；wan2.6-image 真实调用返回 1 张。
- 未验证：新提示词在真实视频上的画质提升（需要真实视频生成，待用户授权后用剩余额度复测）。

## 已知局限

- 复杂任务（多镜头、角色一致性）仍会读取 2–5 个 Skill，偶有 1–3 次提交修正。
- Producer 系统提示词增加约 3,700 字符，每轮固定开销约 +13%；由轮数下降抵消。
- A/B 每任务单次运行，结论是方向性的；可在后续真实冒烟中持续记录。
