| c6 必须 wan2.7、不要 happy-horse | 模型约束 | ✅ wan2.7-t2v | ✅ |

**总体判断**：
- 简单任务上，v2 更快（少 20–40 秒、少约 7 轮调用），计划质量相当。v3 的额外开销来自加载 Skill 与读取 Schema。
- 复杂任务和非模板任务上，v3 明显更强：它能自主决定技术路线、按需协作、组合节点；而 v2 只能套配方或先追问。
- 多 Agent 协作是真实发生的，也是按需的：简单任务从不委派，长片只委派了确实需要的 Director。

## 留给 Codex 的后续问题（PLAN “V-Gate3 后续”）

1. **选择门**：Plan IR 需要“用户从多个预览候选中选一个、下游引用所选结果”的能力（c5、多张定妆图挑选）。
2. **上下文管理**：加载过的 Skill 和资源永久留在历史中，长片单轮输入 token 最高约 11 万。需要裁剪或压缩旧的工具结果，或为每个 Agent 提供精简的作者手册。
3. **简单任务开销**：简单任务约 9 轮调用。可以把 Blueprint 参数摘要放进 Skill 正文，减少资源读取次数。
4. **死节点检测**：c3 计划中有一张“双人设定图”没有被任何下游引用，白花费用。编译器应对不通往交付物的付费节点给出问题提示。
5. **多参考图的默认模型**：多人同框镜头需要能接受多张参考图的模型。默认选型或问题提示应能引导到可用模型。
