# 默认开启 v3：决策草稿与上线清单

> 状态：**草稿**（Claude，2026-10-22）。V-Gate6 通过后由 Claude 补充评测结论，交用户确认；确认前不改任何默认配置。

## 1. 现状

- **开关**：`AGENT_V3_ENABLED`（`backend/app/config.py`，默认 false）只决定**新建** Run 的 `schema_version`（`api/agent.py: create_run`）。已创建的 Run 保留原版本，切换开关不会改写进行中的任务；同一幂等键重复提交也沿用首次版本。
- **准入**（`agent/release.py`）：
  - `AGENT_ALLOWED_USERS`：逗号分隔的用户白名单，为空表示所有登录用户；
  - `AGENT_ACCEPT_NEW_RUNS=false`：停止接收新任务，已有任务可以跑完。
- **不受影响的部分**：经典 19 节点工作流与其页面、API 不依赖上述开关；v2 Agent 继续保留作为回退路径。
- **结论**：灰度、全量、回滚都可以只靠环境变量完成，不需要改代码。

## 2. 开启前必须满足

| 条件 | 状态 |
|---|---|
| V-Gate6 通过：时长、比例落实；长片单轮峰值 ≤80k token；至少 1 次 c3 进入审核；双人身份抽检结论可接受 | 待测 |
| V13e：成片实测时长加测量误差（否则真实视频会因几十毫秒偏差被打成 attention） | 待 Codex |
| v3 运行指标可查（见第 5 节；现有 `run_metrics` 按 v2 结构编写，不覆盖 v3 的计划节点与 attention 状态） | 待安排（建议 V14a） |
| 一次真实端到端（含少量真实视频）由用户本人作为灰度第一单完成 | **需要用户决定** |

关于最后一项：到目前为止，所有自动化测试和评测按 D-030 都没有生成真实视频。v3 的视频生成复用经典 Job 与适配器，这部分在经典工作流里已经验证过；但 v3 新增的参数链（比例、时长、多参考关键帧、拼接与质检）还没有在真实视频上跑过。建议灰度第一阶段由用户本人发起 1–2 个短任务（例如 10 秒、两镜头），费用由用户确认后产生，结果作为全量前的最后一道验证。

## 3. 分阶段上线

| 阶段 | 配置 | 范围 | 进入下一阶段的条件 |
|---|---|---|---|
| 0 准备 | 保持 `AGENT_V3_ENABLED=false` | — | 第 2 节前三项完成 |
| 1 内部灰度 | `AGENT_V3_ENABLED=true`，`AGENT_ALLOWED_USERS=<用户本人 ID>` | 只有用户本人能创建 Agent 任务 | 1–2 个真实端到端任务成功交付，没有 attention 卡死；检查费用与预估相符 |
| 2 小范围 | 白名单扩到少量内部或受邀用户 | 少数用户 | 连续一段时间（建议 1–2 周）指标达标（第 5 节） |
| 3 全量 | 清空 `AGENT_ALLOWED_USERS` | 所有登录用户 | — |

注意：`AGENT_ALLOWED_USERS` 控制的是整个 Agent 模式的准入，不区分 v2/v3。阶段 1、2 期间，白名单外的用户无法创建任何 Agent 任务（经典工作流照常可用）。如果需要“白名单内用 v3、其他人继续用 v2”，要新增按用户选择版本的开关，属于小改动，需另立任务。

## 4. 回滚

1. **只停新任务的 v3**：`AGENT_V3_ENABLED=false`，新任务回到 v2，进行中的 v3 任务继续跑完。
2. **暂停全部新 Agent 任务**：`AGENT_ACCEPT_NEW_RUNS=false`，已有任务继续，新建请求返回 `AGENT_DRAINING`。
3. **缩小范围**：把 `AGENT_ALLOWED_USERS` 改回小名单。

三种方式都只改环境变量，重启后端即可生效，不需要数据迁移。上线前应在测试环境演练一次 1 → 2 的切换，确认进行中的 v3 任务不受影响。

## 5. 上线后观察的指标

按 v3 Run 统计（需 V14a 提供聚合视图）：

| 指标 | 关注点 | 建议告警线 |
|---|---|---|
| 规划完成率 | 进入 awaiting_plan_review 的比例（澄清提问另计，不算失败） | 低于 70% |
| 规划耗时与轮数 | 简单任务 / 长片分开统计 | 简单任务 >2 分钟，长片 >8 分钟 |
| 规划费用 | 单 Run 规划 credits | 接近 `AGENT_V3_PLANNING_CREDITS`（默认 20） |
| 单轮输入峰值 | 真实 usage | >80k token |
| attention 率 | 执行阶段进入 attention 的比例，按原因分组（时长、比例、媒体失败、预算） | 高于 10% |
| 局部修复 | 自动批准与人工批准的比例；意图被判改变的比例 | 人工比例突增 |
| 实际费用与预估偏差 | 媒体生成实际计费对比报价 | 偏差 >20% |

## 6. 用户可见的变化（给用户确认）

- 新建 Agent 任务由 v3 处理：先产出可审核的计划（镜头、模型、费用、时长与比例约束），用户批准后才开始生成；
- 预览图、候选图选择、结果审核、局部修改（只重做受影响的镜头）都在同一页面完成；
- 规划本身会消耗少量额度（默认上限 20 credits），这部分在界面上单独显示；
- 经典工作流的入口、模板与页面不变。
