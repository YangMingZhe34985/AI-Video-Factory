# V8 经典路径：开发与验证报告

Claude · 2026-10-27 · 决策 D-066 · 契约 V.25

## 结论

V8 已完成：用户明确表达生产意图（反推提示词、测试提示词、用于生产并保留提示词）时，Agent 用一个 `run_workflow_template` 节点把任务落到经典“系列 + 模板”下执行，提示词版本经经典 PromptSync 写回模板，作业可在经典作业详情页查看；其余需求照常走 v3 私有计划。经典工作流 19 节点 DAG 与经典 API 未改动。

- 路由 A/B（10 条需求，只做规划）：5 条有生产意图的需求里，4 条直接提交经典路径计划，1 条（没说放到哪个模板）用两道选择题确认模板与范围；5 条无生产意图的全部走私有计划，**误触发 0**。测试类任务原样使用用户的提示词。修正 Skill 后，经典路径规划为 2 轮，约 0.34 credits。
- 真实冒烟（不生成视频）：反推提示词（江南水乡参考视频 → t2v / 首帧 / i2v 三条提示词，内容准确）与首帧提示词测试（1 张图）均成功，并写回模板。
- Mock 全链路：三种任务、I2I 批量、共享队列（MQ）路径、提交前逐次校验、写入确认、补丁禁用均有测试。全量回归见交接记录。

## 真实冒烟发现并修复的问题

1. **经典文本节点在 Agent worker 中失去 JSON 降级**：deepseek-v4.1-flash 拒绝 `response_format`（"type is unavailable now"）。为避免 Agent 规划产生隐式付费调用，Agent/MQ worker 中关闭了经典适配器的降级重试，而经典路径作业恰好运行在 worker 中。修复：只对经典路径作业的经典节点恢复经典的降级重试（json_schema → json_object → 不带格式），Agent 规划调用不受影响。
2. **只出首帧图或只出提示词的作业无法打包**：经典打包以视频为主体。修复：只有启用视频分支时编译器才开启打包，否则交付打包会在编译期报错。
3. brief 写成 `deliverable="prompts"` 被拒（多一轮）：已在 Skill 中写明 brief 只能写 video / image。

## 已知限制

- 作业内经典 LLM 节点生成的提示词不在审批范围内（经典路径的固有特性，计划卡已明示）；审批冻结的是分支、模型、参数、初始提示词与素材以及单价。
- 经典路径作业按经典公开作业处理，不再是 Agent 私有作业：用户勾选写入确认即授权写入模板，作业也在经典页面可见。
- 计划卡上的“实验性组合计划”标记对单节点经典路径计划同样会出现。
- 未做视频生成的真实验证（需单独授权）；Mock 已覆盖 t2v、首帧 + i2v、I2I 批量与打包。

## 费用（估算）

文本调用约 37 次（deepseek-v4.1-flash）；多模态理解约 5 次（qwen3.7-plus：2 次反推视频、3 次 Agent 分析视频或图片）；图片 2 张（wan2.6-image）；视频 0。合计约 1–2 元。
