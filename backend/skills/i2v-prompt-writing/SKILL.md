# 图生视频提示词（写作标准 · 已由 Claude 审定 2026-10-22）

本标准提炼自经典工作流的“首帧生图 / 首帧生视频”拆分规则。首帧已经决定了画质、角色外观和场景；i2v 提示词只负责让画面动起来。wan2.7-i2v 默认不扩写提示词。

## 写什么（按顺序写成一段话）

1. **主体指代（一句，可选）**：用简短指代点明主体，例如“画面中的小狐狸”“这位成年女性”，不复述首帧里的服装、五官和场景细节。
2. **主体动态（重点）**：从首帧的静态姿态出发，写具体动作、方向、幅度和节奏，以及自然联动（头发、衣摆、尾巴、耳朵、手中道具的晃动）。用户要求完成的事件写到完成状态。
3. **环境动态**：背景中的运动元素，例如雪花飘落、雨丝、霓虹闪烁、人群穿梭、水面涟漪、烟雾流动。
4. **镜头语言**：一种主要运镜及其速度（固定机位、缓慢推近、平稳跟随、轻微环绕、缓慢拉远），必要时注明景别变化。
5. **声音**：wan2.7 会生成音轨。写环境音或背景音乐的类型与情绪；无对白时写“无对白”。

## 规则

- **不重复静态描述**：首帧已有的外观、服装、背景只做最少指代。大段复述静态特征会让模型重新“抽卡”，导致形象漂移。
- **新元素要合理入画**：首帧里没有的东西不能凭空出现，应从画外进入或随运镜露出；更好的做法是在首帧提示词里预先放进画面。
- **长度与动作量**：一般 60–180 字；5 秒约一个主要动作，10 秒约一段连贯的动作链。不要同时安排互相冲突的动作。
- **单镜头**：不写时间轴、不写多个镜头、不写“切换到”。
- **尾帧续接**：延续上一镜的结束姿态、视线方向和屏幕运动方向，不跳变；并建立真实前置依赖，不能一边声明尾帧连续，一边让两个镜头并行执行。
- **风格保持**：首帧是插画、动画或其他风格化画面时写“保持原图画风与色调”，不引入“写实”等相反风格词。
- **成年人物**：同 t2v-prompt-writing。

## 提交前自检

是否从首帧姿态出发？是否只有一种主要运镜？有没有复述首帧的大段外观？用户要求的动作是否写到完成？声音写了吗？

## 示例（演示数据，必须按实际需求重写，不可照抄）

首帧：雨天的街边，穿黄色雨衣的柯基站在一个小水坑前。需求：柯基跳进水坑玩水，约 5 秒。

> 画面中的柯基先压低前身、尾巴快速摇动，随后轻快地一跃跳进水坑，溅起一圈水花，落地后甩了甩耳朵，雨衣帽子随动作晃动。细雨持续落下，水面泛起层层涟漪。固定机位低角度中景。环境音为雨声、水花溅起声与轻快的爪步声，无对白。

## 失败与修订

本镜头生成失败时，先定位提示被拒、参数、输入工件或服务异常，保留成功产物；只改提示词不能悄悄改变用户硬约束，费用增加或影响下游时按审核策略确认。首尾帧方式的画质尚未验证，见 first-last-frame。
